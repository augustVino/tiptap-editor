# EditorAdvancedDemo 测试用例

## 测试目标

验证 EditorAdvancedDemo（Editor 高级配置 — 生命周期与高级 Props）的所有功能路径，包括 defaultValue 非受控初始化、autoFocus 自动聚焦、id/className/editorClassName DOM 属性、editorProps 透传、onFocus/onBlur/onCreate/onSelectionUpdate 生命周期回调日志、Submit 扩展动态热更新（禁用/启用切换）、日志面板格式与容量限制、以及 placeholder 显示。

## 前置条件

- 页面已加载，当前 tab 切换到「Editor 高级配置」

---

## TC-ADV-001：初始化渲染 — defaultValue 内容显示

| 项目     | 内容                                                                                      |
| -------- | ----------------------------------------------------------------------------------------- |
| 输入     | 页面加载，切换到「Editor 高级配置」tab                                                    |
| 步骤     | 1. 观察编辑器区域                                                                         |
|          | 2. 观察操作按钮区域                                                                       |
|          | 3. 观察事件日志面板                                                                       |
| 预期结果 | 1. 编辑器显示 defaultValue 设置的内容：「这是通过 defaultValue 设置的初始内容。」和「编辑器加载后自动聚焦到末尾。」两个段落 |
|          | 2. 标题「7. Editor 高级配置 — 生命周期与高级 Props」可见                                 |
|          | 3. 一个按钮可见，文字为「禁用 Submit 扩展」，旁边状态文字为「当前: 已启用（Enter 提交）」 |
|          | 4. 事件日志面板展开，显示日志内容                                                         |

## TC-ADV-004：onFocus 回调

| 项目     | 内容                                      |
| -------- | ----------------------------------------- |
| 输入     | 编辑器当前为失焦状态（需先 blur）        |
| 前置说明 | Demo 配置了 `autoFocus="end"`，页面加载时编辑器已自动聚焦。因此测试 onFocus 时必须先使编辑器失焦，再重新聚焦，才能触发回调。 |
| 步骤     | 1. 点击编辑器外部区域（如标题或按钮）使编辑器失焦，确认日志面板新增 `onBlur` 条目 |
|          | 2. 点击编辑器内部重新获得焦点             |
|          | 3. 观察事件日志面板                       |
| 预期结果 | 1. 步骤 1 中日志面板新增 `onBlur` 条目    |
|          | 2. 步骤 2 后日志面板新增 `onFocus` 条目   |
|          | 3. 两条日志格式均为 `[HH:MM:SS] 事件名`  |

## TC-ADV-010：Extensions 热更新 — 禁用 Submit 扩展后 Enter 不触发提交

| 项目     | 内容                                                      |
| -------- | --------------------------------------------------------- |
| 输入     | Submit 扩展当前已启用                                     |
| 步骤     | 1. 点击「禁用 Submit 扩展」按钮                           |
|          | 2. 观察按钮文字和状态文字变化                             |
|          | 3. 在编辑器中输入一些文字                                 |
|          | 4. 按 Enter 键                                            |
|          | 5. 观察事件日志面板                                       |
| 预期结果 | 1. 按钮文字变为「启用 Submit 扩展」                       |
|          | 2. 状态文字变为「当前: 已禁用（Enter 提交）」             |
|          | 3. 按 Enter 后，日志面板中不出现 `Submit` 条目            |
|          | 4. 按 Enter 后，编辑器中产生换行（默认 Enter 行为恢复）   |

## TC-ADV-011：Extensions 热更新 — 重新启用 Submit 扩展后 Enter 恢复提交

| 项目     | 内容                                                      |
| -------- | --------------------------------------------------------- |
| 输入     | Submit 扩展当前已禁用                                     |
| 步骤     | 1. 点击「启用 Submit 扩展」按钮                           |
|          | 2. 观察按钮文字和状态文字变化                             |
|          | 3. 在编辑器中输入一些文字（确保非空）                     |
|          | 4. 按 Enter 键                                            |
|          | 5. 观察事件日志面板                                       |
| 预期结果 | 1. 按钮文字变为「禁用 Submit 扩展」                       |
|          | 2. 状态文字变为「当前: 已启用（Enter 提交）」             |
|          | 3. 按 Enter 后，日志面板中新增 `Submit: onSubmit triggered` 条目 |
|          | 4. 编辑器中不产生换行（Submit 扩展拦截了 Enter）          |

## TC-ADV-012：defaultValue 非受控 — 编辑后内容不通过 state 控制

| 项目     | 内容                                                              |
| -------- | ----------------------------------------------------------------- |
| 输入     | 编辑器已加载，显示 defaultValue 初始内容                         |
| 步骤     | 1. 在编辑器中追加输入 "手动输入"                                  |
|          | 2. 观察编辑器内容                                                 |
|          | 3. 在编辑器外部点击（不点击任何按钮）                             |
|          | 4. 再次点击编辑器                                                 |
| 预期结果 | 1. 编辑器显示初始内容 + "手动输入"                                |
|          | 2. 内容修改后，编辑器不会因 state 重渲染而丢失或回滚              |
|          | 3. 再次聚焦后，内容保持不变（非受控模式，不依赖外部 state 同步） |

| 输入     | 日志面板中已有 20 条记录                                           |

|          | 2. 超出后，最早的记录被移除，仅保留最新的 20 条                    |
